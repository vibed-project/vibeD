# vibeD v0.4.0 — Testing the Bring-Your-Own Base Image feature

v0.4.0 lets an operator replace the image backing any language slot (`node-24`,
`python-313`, `go-123`, `base-al2023`, `static-nginx`) with their own — e.g. a
hardened base — and vibeD **validates** it before routing traffic to it:

1. every image declares a **contract** (OCI label + env): its language and a
   runtime probe;
2. `vibed-agent` exposes **`GET /info`** reporting the language and running the
   probe;
3. the controller **validates** each slot's image (agent reachable + language
   matches the slot + runtime probe passes) and records the result in the
   `vibed-template-validation` ConfigMap;
4. the claim path **hard-gates**: a deploy routed to a slot whose image failed
   validation ends up `Failed` with a `TemplateInvalid` condition.

This document covers the automated tests and the manual scenarios that exercise
each piece.

---

## 1. Automated tests

### Unit (no cluster)

```bash
# agent /info: reports language, runs the runtime probe (ok + failure cases)
go test ./internal/runneragent/ -run TestInfo -v

# validator decision logic: wrong-language / probe-fail / missing-probe /
# contract-mismatch / unreachable, plus ValidateAll+Persist with a fake client
go test ./internal/templatevalidate/ -v

# claim-path hard gate: invalid template -> Failed/TemplateInvalid
go test ./internal/controller/ -run TestClaimingBlockedByInvalidTemplate -v

# everything
make test
```

### Cluster E2E (Kind + agent-sandbox + vibeD)

`test/e2e/cluster_test.go` (build tag `e2ecluster`) covers **both** the happy
path and a **failing image**:

- `TestClusterDeployReachesReady` — a static site deploys to a valid slot and
  reaches `Ready`.
- `TestClusterInvalidImageIsGated` — the e2e install points `node-24` at the
  static-nginx image (declares `static`, not `node`); the test waits for the
  validator to mark `node-24` invalid, then deploys a Node app and asserts it
  is gated to `Failed` / `TemplateInvalid`.

Runs automatically in CI (`.github/workflows/e2e-cluster.yaml`). Locally:

```bash
# 1. Kind + agent-sandbox + the four images built & loaded, installed with the
#    dev overlay PLUS the e2e overlay (the mis-imaged node-24 slot):
helm install vibed deploy/helm/vibed/ -n vibed-system --create-namespace \
  -f deploy/helm/vibed/values-kind.yaml \
  -f deploy/helm/vibed/values-e2e.yaml --wait

# 2. reach the server
kubectl port-forward -n vibed-system svc/vibed 18090:8080 &

# 3. run both cluster tests
VIBED_E2E_URL=http://localhost:18090 make e2e-cluster
```

## 2. Manual testing on Kind

### Prerequisites

Deploy the v0.4.0 stack (the template images must be rebuilt — they now carry
the contract label/env):

```bash
# build + load the images that changed (server, controller, the template
# images that now declare the contract). Adjust to your build flow.
for img in vibed vibed-controller vibed-router \
           vibed-template-static-nginx vibed-runner-node; do
  podman build -t localhost/$img:dev \
    $([ "$img" = vibed ] && echo . || echo "-f cmd/$img/Dockerfile .") . 2>/dev/null || true
done
# (template images use templates/<name>/Dockerfile — build the ones you'll test)

# load into Kind, then install/upgrade with the dev overlay
helm upgrade --install vibed deploy/helm/vibed/ -n vibed-system --create-namespace \
  -f deploy/helm/vibed/values-kind.yaml --wait

kubectl port-forward -n vibed-system svc/vibed 18090:8080 &
kubectl port-forward -n vibed-system svc/vibed-caddy 18080:80 &
```

### Test 1 — The image contract (`/info`)

Confirm a warm-pool image declares its language and its runtime is present.

```bash
POD=$(kubectl get pods -n vibed-apps -l vibed.dev/template=static-nginx \
  -o jsonpath='{.items[0].metadata.name}')
kubectl exec -n vibed-apps "$POD" -- wget -qO- http://localhost:9000/info
```

**Expect:** `{"language":"static","agentContract":"1","runtimeProbe":"nginx -v","runtimeProbeOK":true,"runtimeProbeOutput":"nginx version: ..."}`.

### Test 2 — Validation status of the shipped images

The controller validates every slot within ~2 min of startup. Use the CLI
(reads from the cluster, works from anywhere; exits non-zero if any slot is
invalid):

```bash
vibed validate-images                 # or: vibed validate-images -namespace vibed-apps
# TEMPLATE      VALID  IMAGE                              DETAIL
# static-nginx  yes    .../vibed-template-static-nginx..  static
# node-24       yes    .../vibed-runner-node...           node
```

Or read the raw status / the Prometheus metric:

```bash
kubectl get configmap vibed-template-validation -n vibed-apps -o yaml
# metric on the controller's :8081/metrics:
#   vibed_template_validation{template="node-24",result="invalid"} 0
```

**Expect:** one entry per enabled slot, each `"valid":true` with the language
the agent reported. (Bad images show `"valid":false` + a `reason`, the CLI
prints `NO`, and `result="invalid"` goes to 1.)

### Test 3 — A failing image is gated (the negative path)

Reinstall with the e2e overlay, which deliberately points `node-24` at the
static-nginx image (wrong language):

```bash
helm upgrade vibed deploy/helm/vibed/ -n vibed-system \
  -f deploy/helm/vibed/values-kind.yaml \
  -f deploy/helm/vibed/values-e2e.yaml --wait

# wait until the validator records node-24 invalid:
kubectl get configmap vibed-template-validation -n vibed-apps \
  -o jsonpath='{.data.node-24}'; echo
# -> {"template":"node-24","image":"...static-nginx:dev","language":"static",
#     "valid":false,"reason":"expected language \"node\" ... image declares \"static\"",...}

# deploy a Node app (routes to node-24) and watch it get gated:
mkdir -p /tmp/n && printf '{"name":"x","dependencies":{"express":"^4"}}' > /tmp/n/package.json
printf 'console.log("hi")' > /tmp/n/index.js
( cd /tmp/n && COPYFILE_DISABLE=1 tar -czf /tmp/n.tgz . )
curl -sS -X POST http://localhost:18090/v1/deploy \
  -F 'source=@/tmp/n.tgz;type=application/gzip' \
  -F 'metadata={"name":"nodetest"};type=application/json'

# the app must end up Failed with TemplateInvalid (NOT Ready):
kubectl get vibedapp nodetest -n vibed-apps \
  -o jsonpath='{.status.phase} | {range .status.conditions[*]}{.reason}:{.message}{"\n"}{end}'
```

**Expect:** `phase=Failed` and a condition `TemplateInvalid: template "node-24"
image failed validation: expected language "node" ... image declares "static"`.

### Test 4 — Bring your own image (override a slot)

Point a slot at your own image and confirm it validates + serves. Easiest
hardened-ish demo: a custom static image built on the contract.

```bash
# build YOUR image satisfying the contract (see docs: Custom Base Images).
# Minimal: reuse the shipped agent + a hardened nginx base, keeping
#   LABEL dev.vibed.template.language="static" + ENV VIBED_TEMPLATE_LANGUAGE/PROBE.
podman build -t localhost/my-hardened-static:dev -f my/Dockerfile .
# load it into kind, then:
helm upgrade vibed deploy/helm/vibed/ -n vibed-system \
  -f deploy/helm/vibed/values-kind.yaml \
  --set warmPools.static-nginx.image=localhost/my-hardened-static:dev --wait

# confirm it validated, then deploy a static site -> Ready + 200:
kubectl get configmap vibed-template-validation -n vibed-apps -o jsonpath='{.data.static-nginx}'; echo
```

**Expect:** `static-nginx` `"valid":true` and a static deploy reaches `Ready`.
For a **private** registry, also set
`--set warmPools.static-nginx.imagePullSecret=<dockerconfigjson-secret>`.

### Test 5 — Deactivate a default slot

```bash
helm upgrade vibed deploy/helm/vibed/ -n vibed-system \
  -f deploy/helm/vibed/values-kind.yaml \
  --set warmPools.static-nginx.enabled=false --wait

kubectl get sandboxwarmpool -n vibed-apps   # static-nginx gone
```

**Expect:** the `static-nginx` warm pool/template is removed; a static deploy
stays in `Claiming` (no pool to bind) — the language is now unsupported until
you provide a replacement image for the slot.

### Test 6 — Turn validation off

```bash
helm upgrade vibed deploy/helm/vibed/ -n vibed-system \
  -f deploy/helm/vibed/values-kind.yaml \
  --set templateValidation.enabled=false --wait
kubectl rollout restart deploy/vibed-controller -n vibed-system
```

**Expect:** the controller logs no validation; the `vibed-template-validation`
ConfigMap is not updated; deploys are **not** gated (every slot allowed). Use
only for air-gapped/trusted installs.

## Observability

- **CLI:** `vibed validate-images` reports per-slot status (exit 1 if any slot
  is invalid).
- **Metric:** `vibed_template_validation{template,result}` on the controller's
  `:8081/metrics` — alert on `vibed_template_validation{result="invalid"} == 1`.
- **Logs:** the controller logs `template image invalid` with the reason.
- **ConfigMap:** `vibed-template-validation` in `vibed-apps` holds the raw
  results.
